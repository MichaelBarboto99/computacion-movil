Gestión del Estado y Formularios

1. ¿Qué es el Estado? (Pág. 123)

El estado refleja la situación actual de la aplicación. Cualquier cambio en los datos que controlan la interfaz (clic en un checkbox, escribir texto) implica una modificación de estado.

Estados Efímeros

Conocido como estado local o de UI. Puede ser gestionado por un solo widget.

Ejemplo: La pestaña seleccionada, la animación de un botón.

Estado de Aplicación

Estado compartido que debe persistir a lo largo de toda la app o sesiones.

Ejemplo: Login de usuario, carrito de compras.

2. Estrategias de Gestión (Pág. 123-124)

setState(): La forma más simple. Ideal para cambios rápidos de texto o animaciones locales.
Provider: Nivel intermedio. Permite compartir datos a través de varios niveles de widgets.
Riverpod: Nivel avanzado. Ofrece una gestión modular, escalable y más fácil de testear.

3. Formularios y Validación (Pág. 124-126)

Para garantizar la seguridad y usabilidad, es fundamental validar que la información ingresada por el usuario sea correcta antes de procesarla.

Flujo de Validación

PASO 1 Usar un widget Form y asignarle una GlobalKey única para identificarlo en el proceso.

PASO 2 Implementar TextFormField. Este widget incluye la propiedad validator.

PASO 3 Definir la lógica de error:

if (value.isEmpty) {
  return 'Por favor ingrese texto';
}
return null; // Todo correcto

PASO 4 Crear un botón que dispare la validación mediante _formKey.currentState.validate().
