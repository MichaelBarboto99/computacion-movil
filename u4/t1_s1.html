Introducción a Microservicios

Los microservicios son un estilo arquitectónico y una forma de desarrollar software donde las aplicaciones se dividen en componentes pequeños e independientes que trabajan juntos para realizar tareas complejas (Pág. 136).

Arquitectura Monolítica vs. Microservicios

Arquitectura Monolítica

Todos los procesos están estrechamente vinculados y se ejecutan como un único servicio. Si un proceso demanda más recursos, es necesario escalar toda la arquitectura (Pág. 136).

Arquitectura Microservicios

La aplicación se construye con componentes independientes que ejecutan cada proceso como un servicio. Se comunican a través de APIs ligeras y bien definidas (Pág. 137).

Características Fundamentales (Pág. 137)

Autonomía

Cada componente puede desarrollarse, implementarse y escalarse de forma independiente sin afectar a otros servicios.

Especialización

Cada servicio está diseñado para resolver un problema particular. Si un servicio se vuelve complejo, se puede dividir en otros más pequeños.

Beneficios de los Microservicios (Págs. 138-139)

Agilidad

Organización de equipos pequeños y responsables de sus propios servicios.

Escalado Flexible

Cada servicio se escala de manera independiente según su demanda específica.

Libertad Tecnológica

Los equipos pueden elegir la herramienta más adecuada para cada tarea.

Código Reutilizable

Módulos pequeños que pueden ser empleados como componentes básicos para otras funciones.

Resistencia

Si surge un error en un servicio, la app puede seguir funcionando (degradación funcional).

Implementación Sencilla

Facilita la integración y entrega continua para llevar nuevas funciones al mercado rápido.
